# 从经验到可发布技能

先确定用户授权的资料范围、目标仓库和可见性；读取当前远端版本及已有技能。已有公开方法优先补充，避免复制多个同义入口。不能把一次任务当作授权导出全部聊天或未来自动发布。

## 提炼

只留下会改变后续决策的输入条件、选择依据、关键不变量、失败边界和交付结构。用新写的通用说明或合成示例表达；私人稿件、原始数据、独特未公开选题和对话原文留在本地。

维护任务的聊天标题、ID、置顶关系、文件路径、操作回执和恢复清单同样属于私有上下文，即使没有消息正文也不随技能发布。把经验改写成通用决策规则，不直接复制真实任务脚本中的白名单、目录名或用户特定的时间界限。

入口保持简短，细节分进按任务读取的参考资料。脚本路径作为参数，凭据由运行环境提供，不嵌入示例。现有第三方技能只链接来源，复制前核对许可和署名；软件许可不能替代数据、论文和图片的许可。

## 发布前

1. 从干净工作树明确列出本次新增/修改文件。检查内容、文件名、元数据、测试样本和 Git 差异。私有备份不进入仓库。
2. 用 `scripts/scan_release.py --root <仓库> --manifest <文件清单>` 扫描白名单；清单是 JSON 字符串数组。扫描拒绝越界、符号链接、非文本、常见凭据和私人路径。输出定位而不打印命中原文。
3. 人工核对机器扫描难以识别的未发表研究构思、可重识别组合、私有组织信息和第三方材料；“零命中”不等于零隐私风险。
4. 验证技能元数据、引用目标与新增脚本的实际行为。区分语法检查、模拟测试和真实数据复现。
5. 只暂存已审阅的白名单文件。提交前再检查 staged diff、文件清单和提交者邮箱；用已经验证的公开身份或 GitHub noreply 地址。尊重用户本轮发布授权，不重复询问已明确的事项。

同步失败时保留本地成品和提交，说明失败点；不改推其他仓库，不绕过分支保护，不强制覆盖远端。交付包含实际远端链接、验证范围、保留在本地的内容类别和未完成事项。
