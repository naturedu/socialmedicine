# 第二步：顶刊临摹与带图表的论文框架

本步学习真实高水平论文怎样提出问题、安排证据和使用图表，再把这些功能转为本研究框架。“顶刊”以用户目标和学科判断为准；不是给任何稿件套同一组章节或图形。

## 1. 选择能解释的标杆

承接[范文库](01-journal-corpus.md)，给每篇入选文章一个明确用途：目标刊写法、相近设计、关键方法、图表表达或讨论逻辑。先精读少量代表作，再针对缺口补文献。

学科、研究问题或设计差异较大时，分别标注“可迁移功能”与“不可直接迁移条件”。不能因为某文章发表在高水平期刊就推定其分析最适合当前数据。

对主要标杆保留以下来源卡：

```text
benchmark_id:
title / journal / year / stable_id:
official_url / full_text_version:
read_sections / unread_sections:
reason_selected:
transferable_structure:
conditions_that_do_not_transfer:
```

## 2. 先看真实原图和所在段落

用户要求“参照原图”“带图表框架”时，应打开实际论文图表及对应图题、结果段和必要方法，不能凭标题、搜索缩略图或模型记忆描述版式。

PDF 记录文档页码；印刷页码不同则两者并列。HTML 没有页码时记录图号、图题、章节和锚点链接，不编造页码。多面板图记录面板字母，补充图使用原有编号。

| 标杆定位 | 观察内容 | 用于本研究的设计决定 |
|---|---|---|
| 原图编号、面板、页码或锚点 | 比较对象、轴、分组、信息层次 | 需要读者回答什么问题 |
| 图题和图注 | 单位、分母、统计量、缩写、误差线 | 本图必须解释哪些口径 |
| 对应方法位置 | 数据如何进入图、模型和处理步骤 | 本研究是否具备同类条件 |
| 首次引用图表的结果段 | 首句任务、报告顺序、关键差异 | 结果段如何围绕图表推进 |
| 讨论中的回扣 | 发现如何改变理解、限制是什么 | 允许讨论到哪一层 |

需要向用户展示参考原图时，优先提供可访问的来源链接或允许展示的预览，并注明出处。能访问不等于允许转载；论文、演示或公开仓库中的再利用应核对许可与署名要求。

原图暂不可读时保留精确来源和待访问状态，可以先出原创布局草案；不能把草案冒充已核对的原图，也不能宣称复刻了真实图形。

## 3. 临摹论证功能，不搬运句子

逐段记录“这段完成什么”，而非整理可直接拼贴的句库。可用以下拆解表：

| 位置 | 段落功能 | 论断与支持材料 | 与下一段的关系 | 本研究对应任务 |
|---|---|---|---|---|
| 引言开头 | 定义问题及研究对象 | 领域证据或现实事实 | 引出具体缺口 | 写本研究问题及范围 |
| 引言收束 | 缺口、目的或问题 | 已检索到的不足 | 进入可回答的设计 | 明确研究目标而非夸大创新 |
| 方法 | 说明证据怎样生成 | 数据、样本、测量与分析 | 使结果可解释 | 列现有方法与待补细节 |
| 结果 | 逐步回答问题 | 表、图、估计值及不确定性 | 形成证据链 | 按结果任务排列图表 |
| 讨论 | 解释发现及边界 | 本文结果和外部证据 | 回答读者可如何使用 | 对照证据写解释与局限 |

该表是拆解工具，不是所有文章必须采用的章节模式。理论、质性、方法、综述等研究依照其实际证据结构调整。

用自己的措辞重建逻辑，不复制标杆独特表达、数据、结论、示例或图形素材。借鉴分析方法时核对假设和引用；不能把“范文也这样做”当作本研究方法合理性的充分依据。

## 4. 提炼本研究的中心论证

依据实际材料写清三件事：研究回答什么问题；最直接的证据是什么；读者能够据此理解或判断什么。没有结果时使用研究问题和分析计划，不预写肯定性结论。

将现有材料分为“可直接支撑”“需分析或核验”“目前无数据”。发现关键问题无法由当前设计回答时，提出缩小问题或补充证据的方案，不通过语言包装跨越缺口。

建立主线：`问题 → 数据/材料 → 测量或分析 → 发现 → 解释与边界`。每个箭头都应有理由；理论假设、实证结果和推测机制分别标注。

## 5. 先定图表任务，再嵌入正文

每张计划图表分配稳定 ID，先写它承担的科学任务，再选择图型。图号可随稿件调整，稳定 ID 用于追踪数据、正文和导出文件。

| 图表卡字段 | 填写要求 |
|---|---|
| 科学问题 | 用一句话说明读者看图后应能回答什么 |
| 数据或证据 | 指向实际数据表、变量、材料段落或文献位置 |
| 方法 | 计算、编码、模型、分组和必要假设 |
| 拟展示内容 | 比较对象、单位、分母、不确定性和面板任务 |
| 结果段嵌位 | 所在节、段落任务、首次引用位置 |
| 讨论回扣 | 能支持的解释，以及不能据此推断的内容 |
| 标杆依据 | 原文链接、图号/页码，以及借鉴的具体功能 |
| 当前状态 | 已有结果/待分析/仅布局；缺口与下一步 |

这样形成每图的完整连接：**科学问题 → 数据 → 方法 → 结果段 → 讨论**。正文不是按编号逐图复述，而是让图表分别承担证据任务。

一图一项主要任务，多面板可以共同回答一个问题。两个图表高度重复时，考虑合并、择一或移入补充材料；不要为了像标杆而增加没有证据价值的面板。

## 6. 输出带图表嵌位的框架

框架至少到段落功能层，并显示证据来源及图表位置。可采用以下形式，标题和层级依目标刊调整：

```text
章节 / 小节：本节回答的问题
段落 A：作用；拟写论断；数据或引文来源；尚缺信息
[嵌位 Figure F01：科学任务；面板方案；图题工作稿；状态]
段落 B：如何解释 F01；要报告的量；与下一问题的关系
[嵌位 Table T01：变量/列/行结构；统计口径；状态]
本节到讨论的连接：允许的解释；需保留的边界
```

主文优先保留支撑中心论证的证据；补充材料承接详细方法、额外结果、稳健性或完整清单。按期刊限制和科学必要性决定，不预设固定图表数量。

已有真实结果时，可写带实际数据的段落草稿；同时保留数值来源。只有研究计划时，写预期报告的字段和判断条件，不写“结果表明”或虚构趋势。

## 7. 缺数据时的可交付边界

缺数据不妨碍完成科学问题、段落角色、空表头和原创布局，但这些产物必须标记为“布局占位/待分析”。

- 用字段名、面板区域、变量关系和说明文字表示计划；不要放貌似真实的点、柱高、曲线或 P 值。
- 用户明确需要教学模拟图时，所有模拟数值及图题显著标注；与研究成品分开保存。
- 不把待核验事实改写成流畅确定句；在框架旁保留具体补证据任务。
- 框架可交付并继续制作不依赖缺失结果的图表部分，不因单个缺口停下全部工作。

## 完成本步的判断

交付重点范文的论证/原图定位表、本研究带图表框架，以及待补分析或证据清单。读者应能从任一图表找到科学问题、数据来源、方法、结果段和讨论边界。

进入[第三步：图表制作](03-figures-tables.md)前先检查图表任务与数据条件；证据和结构稳定后再进入[第四步：文字润色](04-evidence-led-prose.md)。后续数据或分析改变结论时回到受影响的图表卡和段落，不机械维持旧框架。
