# 声明逐项核对：事实、确认、落文与同步

用于新稿、改投、技术退回或声明修订。声明的标题、必填项、放置位置由目标期刊当前指南和本轮编辑来信确定；以下是核对维度，不是所有期刊统一必须出现的一套段落。

## 1. 建立本篇研究的事实底稿

优先读取本篇已提供的批准材料、登记记录、作者信息表、资助资料、协议、当前稿件及明确确认记录。确认过且无冲突的信息直接使用，不重新发同一问卷。不能从另一篇论文、类似模板、旧助手生成句或看似日期的批准号推定事实。

同一事实出现冲突时，比较适用研究、材料版本、原始记录及最新明确更正；不能简单“选最后出现的数字”。只有作者能回答的问题集中一次询问，并给已有内容、冲突位置及需要补齐的具体字段。

一个复合问题收到“是”并不自动补全多个未知字段；已有明确语境可确定的内容照用，剩余必要歧义用最短问题澄清。基金编号、伦理编号、登记编号与有效期各有含义，不能互相代填。

作者确认与文件核验分别记录。有清楚的作者确认但尚未查看原始证明时，不把它升级为“已查原件”；期刊没有要求提供附件时，也不额外设置每条声明均须重新出具签字证明的门槛。关键冲突、缺失事实或期刊明确要求的证明仍须解决。

## 2. 声明矩阵

| 项目与常见英文标题 | 应核对的事实 | 容易遗漏或混淆的点 |
|---|---|---|
| 伦理审批 / Ethics approval | 审查机构准确名称、批准/豁免决定、编号与日期（按实际材料）、适用研究和数据范围 | 伦理审查豁免与知情同意豁免不同；回顾性、匿名化、公开数据不能自动推出豁免 |
| 研究参与同意 / Consent to participate | 谁取得同意、方式、覆盖对象与活动；若豁免，谁作出决定及依据 | 原队列参与同意不自动覆盖新用途；“无需同意”不能代替实际决定 |
| 发表同意 / Consent for publication | 是否含可识别个体信息、照片、案例或其他需特定发表同意的材料，以及适用期刊要求 | 不等于参与研究同意；未涉及需发表同意的材料时按已核实适用性处理，不能机械要求所有论文提供个体发表同意 |
| 研究注册 / Trial or study registration | 注册平台、编号、注册URL、首次注册日期、研究身份及登记状态 | 注册日期不是入组或实施日期；原队列注册与本次二次分析分开交代；不把事后注册写成前瞻注册 |
| 综述方案 / Review protocol or registration | 方案位置、注册信息、日期、版本与偏离计划的记录（实际适用时） | 综述登记不能填进临床试验号字段；无登记不编造号码或暗示已预注册 |
| 作者信息 / Author details | 本稿作者名单、顺序、姓名拼写、机构角标、共同贡献、通讯角色及实际所需字段 | 系统默认第一/通讯作者不一定正确；称谓、学位与贡献均不因身份猜测；英文机构名称及部门层级核对现有正式资料 |
| 作者贡献 / Author contributions | 作者身份/缩写对应、实际贡献与本轮确认，期刊采用的贡献分类 | 不因第一作者、通讯作者或职称推定贡献；缩写重名需消歧；删掉封面信中的贡献段不等于可删主稿要求的贡献声明 |
| 基金 / Funding | 资助机构正式名称、项目编号、资助对象及真实资助角色 | 材料未写基金不等于没有资助；研究资助与文章处理费支持可不同；不自动写资助方未参与 |
| 利益冲突 / Competing interests | 全体适用作者的真实披露及期刊范围 | 未提供不等于无冲突；有资助与有利益冲突并非同一个判断；不能由一位作者身份推断其他人的情况 |
| 数据与材料 / Availability of data and materials | 哪些数据、谁持有、实际访问路径、审批条件、仓储标识及限制 | 本地有文件不等于能公开；“合理请求可提供”也需有权限与实际途径；公开汇总来源与受控个体数据分开 |
| 代码 / Code availability | 哪些代码已提供、版本、仓库/附件位置、依赖和实际可访问性 | 不能把未公开仓库写成已公开；代码存在不等于分析已成功复现 |
| AI 辅助 / AI use disclosure | 实际工具、用途、使用范围及按期刊要求需报告的信息 | 语言润色、筛选、提取、编码、分析与作图用途分开；不把使用日期当检索日期；去模板化不能顺手删必要披露 |
| 致谢 / Acknowledgements | 被致谢的具体帮助、姓名/机构准确性及需要的许可 | 不把未确认的贡献写成作者资格，也不漏记要求披露的帮助；按期刊要求处理许可 |
| 原创与相关稿件 / Originality and related work | 同稿投稿状态、预印本、相关或重叠稿件及本轮需披露事项 | 未提供信息不能代填无重复投稿；预印本与已发表论文按当前期刊政策区分 |
| 全体作者确认 / Author approval | 被确认的是哪一稿、作者名单、贡献和最终提交版本 | 过去版本获同意不能自动覆盖新增作者、数据、结论或实质修订；不因用户要求制作材料便代称所有作者同意 |
| 外部材料许可 / Permissions | 引用或改绘图表、问卷及其他素材的来源、许可范围和署名要求 | 公开可访问或已经引用不等于可转载；仅学习版式与正式再利用的条件分开 |

## 3. 研究范围与日期的分层检查

原始研究、数据共享/访问、本次二次分析可能对应不同来源和范围。按实际情况说明每层依据；不要求所有层都必须有一个新伦理号，也不能把某层批准自动扩大到其他用途。多中心研究按现有审批覆盖方式核查，不能臆定每中心必须另审或一份必然覆盖全部。伦理审批、免伦理审查、取得知情同意和豁免知情同意分别登记；相互替代的决定按实际情况标记不适用，不将它们混写为一项笼统的“合规”。

把适用的时间概念分开：

- 伦理决定日期与批准编号。
- 招募、干预、数据收集、随访或历史数据覆盖期间。
- 首次注册日期、登记更新日期和登记状态。
- 本次二次分析或新增活动的实施期间。
- 首轮/更新/背景检索的执行日期与文献发表时间限制。
- AI 辅助使用日期和声明/稿件修订日期。

时间顺序看似异常时先核查活动性质与依据；历史数据早于二次分析批准日并不能单凭日期断定违规。若材料未交代前瞻/补注册或批准适用活动，不代填结论。

## 4. 四层状态分别记录

使用 `_checks/declarations_register.csv`。每条声明至少留下：

| 层次 | 记录内容 | 通过含义 |
|---|---|---|
| 事实来源 | 来源类型、位置、适用研究/版本、核查深度 | 知道事实来自哪里；题录、作者说明和原件不混称 |
| 作者确认 | 是否需要确认、已有确认位置及版本 | 对需要作者负责的内容有相应确认，或有明确不适用理由 |
| 实际落文 | 本稿采用的表述、文件版本、页码/段落/对象 | 已打开文件看到正确内容，不是仅给出一句建议 |
| 跨处同步 | 其他需出现的文件/字段、比对结果及未访问项 | 需要一致的内容已核对；未访问系统不标为已同步 |

适用性使用 `UNASSESSED / APPLICABLE / NOT_APPLICABLE`。声明审查总状态沿用 `NOT_CHECKED / PASS / FAIL / NEEDS_AUTHOR / NOT_APPLICABLE`。来源状态可记录 `NOT_CHECKED / AUTHOR_REPORTED / DOCUMENT_VERIFIED / CONFLICT`；作者确认、落文和同步分别使用 `NOT_CHECKED / DONE / NOT_APPLICABLE`。不适用均应有理由，不能通过一键填写 N/A 消除缺项。

事实不适用与期刊不要求声明是两回事：期刊若要求写出正式的“Not applicable”，仍须在 `required_locations` 中列出位置并完成落文、同步；`applicability=NOT_APPLICABLE` 不自动使其他状态也成为不适用。

`PASS` 要满足本项适用的证据、确认、落文与同步要求。仅找到一条伦理句子、仅填一个日期、仅收到作者回答，不能自动标为整项通过。不要把“需要作者提供”用于本地材料已经足以解决的内容。

## 5. 跨文件和投稿系统怎么核对

以 `03_Manuscript` 的当前确认版本及声明底稿为参照，检查实际需要的载体，不强制把所有声明重复塞进所有文件。

| 载体 | 需要对齐的内容 |
|---|---|
| 01_CoverLetter | 稿名、刊名、文章类型、关键结果及信中实际作出的原创/利益冲突/作者同意等声明 |
| 02_TitlePage | 作者顺序、机构对应、共同贡献、通讯作者与联系方式、期刊要求在此放置的声明 |
| 03_Manuscript | 方法中的研究对象/批准/注册与文末声明一致；清稿和标记稿表达同一事实 |
| 04_Supplementary | 数据来源、方案、注册、分析范围和方法完成情况与主稿对应 |
| 回复信 | 每条声称“已补充/已更正”都指向实际修改位置；不能超出已完成工作 |
| 投稿系统字段 | 当前题名、摘要、作者、伦理、基金、冲突及注册等实际表单字段，按用户授权核对或更新 |

不能因为系统是必填框就选一个未经核实的“无”或“已批准”。无法访问的字段单列待同步；本地制作完成与外部系统写入分开报告。匿名副本按期刊要求隐藏身份线索，不改变真实声明事实，完整资料仍在规定位置保留。

投稿检查表 P20 仅在实际核对本轮涉及的系统字段后才能通过；记录“未访问”不能代替核对。若本轮仅准备本地稿件，P20可按任务范围记不适用并说明，无需为本地组包强行登录系统；实际未访问的字段仍保留未检查状态。

## 6. 消除占位符与处理编辑来信

搜索并逐处判断 `AUTHOR TO COMPLETE`、`TBD`、`待补`、`待确认`、黄色高亮、空括号和模板提示；不能机械删掉它们后把未知事实当作已解决。内部台账允许保留待核，提交版只有事实和适用的正式声明。

编辑要求补充注册日期时核对日期；要求澄清豁免时核对决定及适用范围；不要以更长的通用声明替代缺的事实。依据本轮来信确定主稿是否清稿、标记版放在哪里、回复信格式；不把某次编辑要求永久泛化。

完成后把未决项写入 `_checks/issue_log.csv`，明确影响的是某个声明、文件还是最终提交。已确认内容不重复询问；缺项集中说明。只有依据事实补齐并实际检查各处同步后，才关闭相应问题。
