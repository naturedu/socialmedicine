# Skills Paper：从目标期刊到投稿包

把研究材料推进为有证据、有图表、可复核的完整稿件。按用户指定的五步工作；已完成的阶段从权威版本接续，不机械重做。只要求润色或作图时，完成对应阶段即可。

## 先确定当前版本与任务

- 优先读取用户材料、当前项目记录及用户要求回顾的相关历史。区分原始记录、用户确认的事实和旧助手建议；旧回复不是数据或文献证据。
- 用简短项目卡记录目标期刊与文章类型、核心科学问题、数据来源与研究设计、当前权威稿件、已确定图表、语言、交付位置及未解决问题。仅询问实际阻断工作的缺项，能完成的部分继续。
- 新指令优先于历史偏好。已有图表、作者顺序、主要结局和数据口径不得无说明地改掉；修订以新版本保存，并说明实质变化。
- 历史回顾说明范围：目录覆盖、实际阅读的聊天及访问限制分开报告。对话原文、身份信息和真实项目路径不写入可公开技能。

## 五步及交付

只读取当前步骤的参考文件；跨步骤时再加载下一份。

| 步骤 | 需要落实的工作 | 阶段交付 | 操作说明 |
|---|---|---|---|
| 1 目标期刊抓文章 | 核实当前作者指南；检索同刊、同类研究及方法适配范文，合法获取全文 | 期刊要求表、检索日志、去重题录、全文状态、精读候选 | [01 期刊语料](references/01-journal-corpus.md) |
| 2 顶刊临摹与带图表框架 | 拆解科学问题、论证次序和真实原图；转化为本研究段落与图表位置 | 带原图出处的范式对照、正文提纲、逐图逐表计划及占位框架 | [02 范文与框架](references/02-benchmark-framework.md) |
| 3 图表制作 | 从本研究数据制作图表，解释每图回答什么问题 | 可编辑图源、绘图数据和代码、投稿导出、图题图注、质量检查 | [03 图表](references/03-figures-tables.md) |
| 4 去模板化文字 | 把“去人味／去 AI 味”落实为具体、自然、证据约束的学术表达 | 完整清稿、必要的标红稿、重要措辞变化和未决事实 | [04 文字](references/04-evidence-led-prose.md) |
| 5 投稿前审核 | 核对科学证据、期刊要求、全包一致性和渲染效果 | 00—04完整包、审核结论、缺项与上传文件映射 | [05 投稿审核](references/05-submission-preflight.md) |

每步应产出文件或可直接使用的内容，不能仅介绍“如何做”。没有数据时可交付设计稿和待填表；明确标记，不画虚构结果。

## 固定的交付主目录

```text
paper-project/
├── 00_原始数据/
│   ├── raw/                 原始输入，分析时不覆盖
│   ├── analysis/            派生数据、统计结果和数据字典
│   ├── code/                清洗、统计与绘图代码
│   └── provenance/          来源与版本记录
├── 01_CoverLetter/          投稿信
├── 02_TitlePage/            题名页及作者信息
├── 03_Manuscript/           含正文图表的完整手稿
│   └── figures/             独立导出与可编辑图源
├── 04_Supplementary/        补充方法、结果、图表与适用清单
├── _work/                  抓文、范式、框架及修改工作底稿
└── _checks/                审核证据、未决事项与交付清单
```

00 是项目内部的数据与复现层，不代表原始个体数据可以公开或必须交给期刊。按实际授权和期刊要求确定上传对象。正文必须包含主图表；若期刊另要求单独上传图表，再从同一权威版本导出，保留整合阅读版。期刊不需要某份材料时标明“不要求”，不要为凑目录编造内容。

## 可重复的工具

使用 [paper_package.py](scripts/paper_package.py) 初始化目录和可填写台账；重复执行只补缺失文件，不覆盖已有内容。脚本只用 Python 标准库，不联网、不上传、不生成研究结果。

```bash
python scripts/paper_package.py init --root /path/to/paper-project
python scripts/paper_package.py inventory --root /path/to/paper-project
```

在实际运行时把脚本和项目参数替换为真实路径。清单输出在 `_checks/package_inventory.json`，只证明结构、文件大小和哈希，不证明科学正确、文献已核验或投稿就绪。`_checks/submission_checklist.csv` 的初始状态均为 `NOT_CHECKED`，必须根据真实检查更新。

## 工具选择与证据边界

- 期刊规则、投稿入口和文献身份以实际访问的官网与权威记录为准，记录核查日期；不能把旧期刊规范写成永久要求。
- 环境有文献检索、Word/PDF、图表、语言润色或 cover letter 技能时，按当前任务选择并读取；本技能不依赖某一台电脑上的其他技能，也不要求全部加载。工具缺失时交付可用的文本/代码/表格并说明未验证环节。
- 顶刊范文用于论证结构和展示方法，不复制其独特文句、结果或未经许可的图作为本研究成果。原图仅作有来源的学习参考，投稿使用原创图或已获许可的材料。
- 结论须有材料支持：保留分母、单位、效应方向、区间、引文和不确定性；不按显著性筛结果，不为闭合流程倒造数据，不把相关性改成因果关系。
- “去人味”不指抹去作者判断或绕过检测器。去空话、机械句式和操作痕迹，同时保留重要限制及适用的 AI 使用披露。
- 投稿前审核不等于登录系统或正式提交；有相关授权时继续执行授权范围内的操作，不把此技能视为永久代投授权。

## 最后交付

给出实际文件链接、所用权威版本、已完成的核查层次和仍影响使用的缺项。区分 `READY_FOR_AUTHOR_SUBMISSION`、`NEEDS_AUTHOR`、`BLOCKED`；状态须对应审核证据。不得用“无缺陷”“保证接收”替代核验。
