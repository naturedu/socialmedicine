# 客户端更新、缓存与旧聊天维护

只执行用户本轮请求或已明确授权的维护范围。客户端更新、缓存清理、聊天归档是不同操作；沿用已确认的选择，不把其中一项扩展成全部操作。

## 检查更新

优先使用客户端自带更新检查；若有 `check_app_update`，调用一次并按返回状态处理，不例行轮询。`up_to_date` 只表示当前安装渠道没有适用更新；`busy`、`unavailable` 或错误不能解释为已是最新版。

记录运行中应用的版本、构建和更新状态。操作系统软件包版本可能采用不同编号，不直接据此判断新旧。检查成功不等于完成安装；安装后需核对实际版本，待重启时明确报告。使用当前官方安装渠道；正在运行的任务需在重启前妥善处理，不为更新强制终止工作。

## 时间范围与保护对象

把“超过 N 天”转成用户时区下的明确截止时间。聊天使用最后更新时间；缓存文件要结合时间戳语义和任务状态，不能仅凭文件名或旧修改时间判定过期。日期、范围、项目归属不明的条目暂留，并在结果中说明。

先建立置顶聊天、置顶项目、关联工作目录及当前任务的保护集合。保护关联材料，而不只是保护置顶条目本身。聊天附件、项目数据、会话数据库、登录数据和运行依赖不当作一般缓存处理。

## 归档旧聊天

使用应用提供的列表、读取与归档工具，分别分页取得所需来源，记录读取范围和未完成的分页。列表只是元数据，不等于通读消息。

标题仅用于筛选候选；结合项目归属及最近内容判断，必要时向前读取。看似日常闲聊的标题也可能包含研究成果或当前任务决定，混合内容和关联不确定的聊天保留。对仍关联计划任务或自动化的聊天，先核对归档影响；未确认已停用时保留。

归档前在本地记录精确 ID、原始标题、最后更新时间、理由和当前状态，并复核置顶及活跃状态。沿用用户已授权的归档范围，不改为永久删除，不直接修改应用数据库。逐项记录回执，最后用归档列表核对实际成功的 ID，并复核置顶保护集合。恢复方式以对应来源当前支持的工具或界面为准。

## 清理缓存和临时文件

只清理用途明确、满足截止时间且与保护对象无关的临时内容。先列出候选、字节数与判断依据，再执行已授权的删除；扫描不触碰文件正文，确需内容判别时只读取必要部分。

- 下载任务可能保留资源原有时间戳。Windows 的 BITS 或浏览器更新临时文件，应检查当前下载任务的本地目标及父目录关联；仍被引用的文件保留，不因扩展名为 `.tmp` 就删除，也不为清理而取消下载。
- 活跃浏览器缓存、索引和数据库不按单个旧文件直接清理。确需修复时，通过应用支持的方式，在相关应用正常退出后处理；不删除整个配置或用户数据目录。
- 删除前重新核对规范化绝对路径位于明确的允许目录内，路径祖先和目标没有符号链接、junction 或其他重解析点，且文件类型、大小、时间与清单一致。被占用、已变化或无法访问的条目跳过并记录。
- Windows 文件操作保持在同一个 PowerShell 流程中，使用 `-LiteralPath`。递归删除前验证最终目标和全部待删内容；优先按清单删除文件，再移除已确认空的目录。
- 空 Git 临时目录需要核对它确属临时区域、未被配置或活动任务引用，且无提交对象、引用、工作文件或其他成果。不能把用户工作仓库套用这一规则。

## 验收与报告

分别报告候选数、成功数、跳过数、归档验证结果和实际删除内容的逻辑字节数。只有测量过磁盘可用空间变化，才能报告实测空间增量；只有做过可重复的前后对照，才能声称性能改善。没有符合条件的大缓存时如实报告，不放宽时间或用途条件来凑清理量。

含聊天标题、ID、私人路径或任务背景的检查记录与回执仅保存在本地。可发布的技能只保留通用判断规则，不携带真实清理清单。
